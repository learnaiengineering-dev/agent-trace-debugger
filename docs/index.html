Agent Trace Debugger

An agent run can finish in the same time as before and still be worse: one more error, hundreds more tokens spent in failed calls. This tool shows where time and tokens went, compares a run with a baseline, and fails the build when it regresses.

Try it

This run finishes in the same 100 ms as its baseline, but one span now fails and burns more tokens. Click a row to inspect a span, or open "Edit the trace" and paste your own spans.

Own time is a span's duration minus the union of its children, so parallel work is not double-counted. Tokens must be each span's own usage. Everything runs in your browser and nothing is sent anywhere.

Ways to use it

Command line

Run it locally or in any CI. Exit code 1 means a limit was exceeded.

GitHub Action

One step in a workflow. Writes a job summary and an optional HTML timeline.

Python library

Call analyze() and compare() from your own tooling.

Embeddable widget

Show a trace and its gate result on your own site, docs or dashboard.

Claude skill

Let a coding agent run the debugger and explain what changed.

Install and run

pip install agent-trace-debugger
trace-debug current.jsonl --baseline baseline.jsonl --max-wall-increase 50 --html report.html
# exit 0 passed, 1 a limit was exceeded, 2 bad input

The gate

OptionDefaultFails when
--max-new-errors N0There are more than N extra errors compared with the baseline.
--max-wall-increase MSoffWall time grew by more than MS.
--max-token-increase NoffTotal tokens grew by more than N.
--max-failed-token-increase NoffTokens in failed spans grew by more than N.
--max-errors NoffThe absolute error count is above N (works without a baseline).

From Python

from agent_trace_debugger import analyze, compare, parse_trace

current = analyze(parse_trace(open("current.jsonl").read()))
baseline = analyze(parse_trace(open("baseline.jsonl").read()))
result = compare(current, baseline, max_wall_increase=50)
if not result.passed:
    print("\n".join(result.failures))

Embed the widget

The widget is one JavaScript file with no dependencies. Copy agent-trace-widget.js next to your page (host it yourself; there is no CDN to depend on), then add the element:

<script type="module" src="/assets/agent-trace-widget.js"></script>

<agent-trace heading="Last agent run" max-wall-increase="50">
  <script type="application/x-ndjson" data-role="current">
{"id":"run","name":"Agent run","start":0,"end":100,"status":"ok","tokens":0}
  </script>
  <script type="application/x-ndjson" data-role="baseline">
{"id":"run","name":"Agent run","start":0,"end":98,"status":"ok","tokens":0}
  </script>
</agent-trace>

The baseline is optional. Or show a ready-made page in an iframe using embed.html:

<iframe src="/assets/embed.html" title="Agent trace" width="100%" height="560" loading="lazy"></iframe>

Attributes

AttributeDefaultWhat it does
headingnoneOptional title above the result.
editableoffAdds an "Edit the trace" panel so visitors can paste their own spans.
themeautolight or dark. Auto follows the visitor's system setting.
max-new-errors0Allowed extra errors compared with the baseline.
max-wall-increasenoneAllowed wall-time increase in ms (needs a baseline).
max-token-increasenoneAllowed total-token increase (needs a baseline).
max-failed-token-increasenoneAllowed increase in tokens spent in failed spans (needs a baseline).
max-errorsnoneAbsolute error limit.

Use it from JavaScript

const el = document.querySelector("agent-trace");
el.data = { current: jsonlText, baseline: otherJsonlText };   // text or arrays of span objects
el.addEventListener("trace-result", (e) => {
  console.log(e.detail.gate.passed, e.detail.gate.failures);   // same shape as the Python report
});

// Or use the logic without the element:
import { parseTrace, analyze, compare } from "/assets/agent-trace-widget.js";
const report = compare(analyze(parseTrace(current)), analyze(parseTrace(baseline)), { maxWallIncrease: 50 });

The trace-result event bubbles and carries the report, or null when the input is invalid. The widget's numbers are checked against the Python package with a shared golden file, so both give the same results.

Security and content policy

  • No network access. The widget never fetches or sends anything. It only reads the trace you give it.
  • No inline scripts or style attributes in the markup. Styles come from a constructed stylesheet and positions are set through the DOM, so a strict script-src 'self' policy works. A browser without constructed stylesheets falls back to a <style> element, which a strict style-src policy would block, leaving the widget unstyled.
  • Trace text is never run as HTML. Span names are untrusted (they can come from model or tool output) and are inserted as plain text.
  • Pin the file. If you load it from a shared location, add a subresource integrity hash:
openssl dgst -sha384 -binary agent-trace-widget.js | openssl base64 -A
# then: <script type="module" src="..." integrity="sha384-<hash>" crossorigin="anonymous"></script>

For your organisation

QuestionAnswer
Does it send data anywhere?No. The CLI and the widget make no network calls and have no telemetry. Traces stay on your machine.
Can traces hold sensitive text?Yes. Span names and attributes can include prompts or customer data. Redact before sharing a report, and treat trace files like logs.
What does it depend on?Nothing at runtime: the Python package has no dependencies and the widget is one file.
Can it run offline or behind a firewall?Yes. Mirror the package on your internal index, or vendor the single widget file.
Are results repeatable?Yes. The same inputs always give the same numbers and the same HTML report.
Is the output stable?The JSON report has a schema_version and the exit codes are documented. Pin an exact version in your pipeline.
How is it released?Published to PyPI from GitHub with trusted publishing, so there is no long-lived upload token to leak.
What is the licence?MIT. You can use, modify and redistribute it commercially. Keep the licence, the file header and the NOTICE.

Limits

  • Token counts must be per span. Cumulative counts would be double-counted in the totals.
  • Clocks from different machines must be normalised before import. OTLP JSON is not read directly.
  • The timeline shows timing as recorded. It does not explain why a span was slow or why a call failed.
  • The widget shows a trace and the gate result. It does not collect traces from your agent.
